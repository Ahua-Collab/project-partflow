# 隐私边界与发布方法

[English](privacy-and-publishing.en.md) · [阶梯工坊 · Stepwise](../README.md)

## 什么可以放进技能包

分发 `SKILL.md`、界面元数据、通用参考、未填充模板、检查器和匿名教程。原始技能有完整文件清单，不能只导出主说明而遗漏模板或脚本依赖。

业务项目与 skill 分开。不要把项目目录、`.git` 历史、角色工作树、daily/progress 记录、机器定位、聊天导出或依赖缓存整体放进技能仓库。 `.gitignore` 只影响未来 Git 跟踪，不能清除已经提交的内容或历史。

## 示例怎样匿名化

使用虚构项目、任务 ID、路径和合成输入。只提炼“先固定输入再比较”“跨界找唯一所有者”“保护停机不等于正常完成”等协作方法。不要照抄真实角色任务链接、用户名、邮箱、账户、私有接口、业务阈值、真实运行数据、提交 SHA 或可识别的私密需求。

以某交易所类型为背景并不需要复制其使用者的实际配置，也不应附上密钥或私有响应。实际接口规格在实施时另查，教学案例不声称当前账户具备任何权限。

## 发布前检查

1. 从明确白名单的 skill 文件生成独立副本；原目录与业务项目只读。
2. 核对所有相对引用完整；查看脚本导入、外部命令与是否包含下载/上传动作。
3. 扫描密钥格式、凭据赋值、私人路径、邮箱、账户与任务定位；人工区分规则文字、合成样例和真实秘密。
4. 排除数据库、行情、订单、日志、聊天、二进制、缓存、链接和历史仓库；检查压缩包实际条目，不能只看目录表面。
5. 运行可用的合成自测，分别记录权限失败、成功复跑和未测试部分；校验原 skill 未改动。
6. 生成最终清单与校验值。公开副本包含通用结论，私人核对依据保留在发布目录之外。
7. 核实目标账户、仓库、可见性与写授权；同名仓库先看已有内容，不覆盖或强推。

这是分发技能的检查方法，不自动授权公开任何新数据。若检查发现真实秘密，先从副本排除并处理已暴露范围；不要在公开问题或报告里复述秘密值。

## 已公开内容如何维护

后续每次更新仍从明确版本生成副本，审查实际 diff 和新增文档。安装者应保留旧版便于回退；技能升级不自动迁移既有项目治理或历史。可采用 Git tag 标记稳定版，但版本号、仓库身份和许可证由发布者按事实决定，不在示例中虚构。
