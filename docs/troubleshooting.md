# 常见问题与处理

[English](troubleshooting.en.md) · [阶梯工坊 · Stepwise](../README.md)

## 每轮都重读 daily、prompt、review，token 很多

先核对项目自己的 AGENTS 是否比 skill 更严格。现行规则默认按角色和阶段读取，上一个 Part、当前任务及前置是重点，更早历史按问题回溯。完整报告落盘，聊天用精确路径与问题 ID 交接；不要反复粘贴整份治理。

同一当前上下文完整保有原文、来源相同且实际哈希未变时才可复用。压缩、交接和新会话会重新触发必读，里程碑与最终验收也完整重读治理。这些是质量边界，不是可随意删掉的浪费。skill 没有 token 计费器、持久“已读许可证”或经实测的节省比例。

## 角色说“完成”，总控却继续等

让回执写清任务 ID、正式 prompt、实际基线/最终提交、报告路径和准确阶段。总控分别核对送达、执行、交付、技术接受、集成与主线 PASS。文件存在、窗口有名字和进程退出都不单独证明业务完成。

## 模板太死，模型不能选择方法

把契约、兼容性、权限、资源与可观察验收列为硬要求，把算法和局部组织写为可调整建议。没有正确性依赖的步骤不要固定顺序。可以调整 Markdown 布局；状态 JSON 的字段、唯一所有权、独立审核和授权边界仍保持。

## 测试全绿，却在复审发现错误

检查测试期望是否忠实于原需求；查看完整受影响函数与调用者，必要时做独立反例。关注取消后的状态一致性、跨循环资源上限、真实回执、时间窗口、边界值和重复恢复。别只重跑实现者的同一套断言；也别把静态关注写成已复现失败。

## A/B 或性能测试反复失败

先固定假设、提交、输入、程序、配置、指标边界与机器负载，分析原失败证据。运行次数不是因果证据。最小定向见证能回答问题时，先用它；相关生产路径变动后再补完整受影响矩阵。无变化的已过检查不机械重跑；旧失败和不同条件不能拼接成一次不存在的完整成功。

详细例子见 [行情研发示例](market-workbench-example.md)。这不是通用统计检验框架，也不承诺少跑固定次数。

## 出现跨模块依赖，是否要开新 Part

通常保持当前 Part，写最小 CR，明确所有者、受影响任务与最迟关闭点。前置由所有者实现并独立审核、合入复验后，主体再限定导入。只暂停依赖该缺口的工作；不因出现 CR 就阻断无关已授权任务，也不提前执行未来 Part。

## `check` 报错

| 报错类别 | 先检查什么 |
|---|---|
| `schema v2 required` / `do not reset` | 是否旧 Day/schema 1 项目；保留历史，先人工恢复，不只改版本号 |
| `fill project owners` / `fill planned tasks` | 是否直接用了空模板；先按认可计划填角色、所有权与任务 |
| `next_part` / `prefix` | 完成索引是否连续；不能跳段或用手改状态补成功 |
| `not final PASS` / `no mainline verification` | 是否仍技术接受、缺主线检查或缺日志 |
| `not integrated` / `missing commit` | 主分支与 Git 对象是否实际存在，迁移是否缺历史 |
| `overlapping ownership` | 所有权使用精确文件或 `/` 结尾前缀，不使用重叠范围或 glob |
| `unsafe relative path` / `path escapes project` | 配置和证据是否项目内相对路径，是否含越界链接 |
| `task started while issue blocks it` | `blocks` 是立即阻断，不是笼统关联；按事实厘清作用，不删门禁骗过检查 |
| `ENOENT` | 所引用的 prompt/review/日志是否在当前项目，或尚未归档 |

脚本拒绝是定位线索，不授权覆盖旧 review、伪造日志或把必需问题改为非阻断。检查器只检查部分结构关系；`ok` 仍须技术审核。

## Node、Git 或沙箱权限不足

文本流程可以继续，自动检查结果标为未执行/受阻。已有工具可用时运行自测；自测需在临时目录初始化合成 Git 仓库，某些沙箱会阻止 `.git/config` 写入。按宿主正常审批方式处理，或人工核验并记录边界，不关闭安全保护，不安装来源不明的软件。

## 新设备找不到角色窗口或任务 ID

先用项目文件和 Git 恢复，重新发现工具与权限。无法自动创建任务时，提供手工创建/转发说明，登记用户确认的角色标题；不能编造 ID 或宣称工具送达成功。旧总控停派工，新总控核对恢复后再转移活动权。

## 旧项目叫 daily/Day-NN

旧 Day 也是逻辑工作单元。按原治理和旧格式继续，保留旧编号、失败与完成结论。schema v2 检查器会拒绝旧格式，不自动迁移。用户明确要求迁移时，逐项映射所有引用并核验历史，不能清空台账重开。

## 什么时候真的需要用户决定

产品方向、缺失的关键事实、超出授权的外部动作和宿主权限可能需要用户决定。任务内选择实现方法、必要验证和修复不应逐步请示。因规则暂停时指出具体文件/条款与受影响动作，保存恢复点，继续其他授权内工作。已有授权不重复索取。
