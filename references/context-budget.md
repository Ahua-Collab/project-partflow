# 保留审核质量，减少重复上下文

## 读取范围

| 时机/角色 | 必读 | 不默认重读 |
|---|---|---|
| 总控首次接手、恢复 | 完整项目书/AGENTS、当前 STATUS/规则、上个 Part 任务的原始/补正 prompt 与最终 review、当前已有记录、开放 CR、Git | 无关更早历史、全仓代码 |
| 总控新 Part 派工 | 重新读取权威 STATUS/开放问题，核对 Git/治理版本；上个 Part、当前任务及前置的 prompt/review；重核本 Part 目标、所有权、依赖及验收原文 | 满足下述条件的已读未变治理原文；不能省略当前状态核验 |
| 实现角色初始化/新任务 | 完整 AGENTS 与正式 prompt、权威 STATUS、自己的所有权/计划章节、上游契约和相关隐私规则 | 其他模块排期与实现、总控全部聊天 |
| 同一 Part 补正/复审 | 原任务要求、最新 review、未关闭问题、真实提交差异、影响到的调用方/测试 | 未受影响模块和已读未变治理原文 |
| 里程碑/最终验收 | 完整重读项目书/AGENTS；全部适用验收项、跨模块路径、最终制品与证据 | 逐轮重复讲述历史过程 |

更严格的项目必读规则优先。索引只帮助定位：先看文件/差异清单，再按需读正文；输出截断必须补读。不得只凭摘要或哈希宣称已读原文。

## 可复用与必须重读

仅当同一任务的当前上下文仍完整保有已读原文、读取范围明确，并核对同一治理来源的实际文件 SHA-256 未变时，才复用该内容，包括连续的新 Part。文件时间、大小或 Git HEAD 相同不足以判断未变。身份、角色、项目根或源路径不同不能复用；不确定原文是否还在上下文就重读。未提交文件读取前后核对哈希，或读取固定提交原文，避免把旧正文与新哈希配对。读取记录只记来源、版本/哈希和实际范围，不建立可跨会话生效的“已读许可”。

新会话、压缩/摘要、交接、换设备时重新完整读取本角色必需原文；治理内容变化、证据冲突时重读相关权威文件全文并追踪影响。里程碑/最终验收不使用治理全文复用豁免。未提交状态本身不等于内容变化，仍以实际文件核验；旧工作树中的哈希也可能是旧版本，先按 recovery 确认权威来源。`gate.mjs inputs` 只给指定根目录的路径/哈希，不认证来源最新、不证明已读，也不覆盖所有任务引用的契约/证据；遗漏的引用单独核对。

派工、写最终 PASS 或推进 STATUS 前，再核对治理版本、被审提交与主线是否仍与依据一致。新改动或并发提交未纳入审核时，暂停相关放行并补验受影响部分；不以此前通过的索引/检查结果代替当前事实。STATUS 的读取与更新由唯一活动总控串行完成。

## 一次存全，按需传递

prompt 和 review 保持完整且能独立恢复；用精确路径、需求/问题 ID、版本与定位引用稳定材料，不反复粘贴整份项目书。补正文件写清本轮变更、仍有效的原要求与必须读取的原 prompt/review，不让接收者靠聊天猜要求。

默认把完整报告存入约定位置，聊天只给 Part/角色/结论、关键问题、提交与文件链接、下一动作。接收任务能读共享文件时，转发“角色+任务+权威根定位+正式 prompt 路径”的短指令即可；不能读文件或用户要全文时立即提供完整可复制文本。每次只提供一种所需转发方式，不要求用户自己摘抄、拼接或填写字段。

日志完整落盘，工具输出先给退出码、计数、失败摘要及定位；发现异常再读相关日志。不能丢弃警告、过滤出虚假的成功或省略审阅者必需证据。检查器可遍历全部历史，但只返回精简结论与失败定位，模型无需每轮接收历史全文。

审核先读 diff、完整受影响函数/契约及相关测试，再沿调用影响扩展。独立复验、主线验证和原有必需矩阵仍保留；已执行且提交、输入、工具链、配置、环境和需求均未变的同一审阅者检查无需机械重跑。实现者测试不替代总控复验，源分支测试不替代主线复验。

## 授权内连续执行

prompt 规定目标、可观察验收、接口和真正的限制，不预写每一步实现路线。角色在范围内自主选择算法、局部结构和调试顺序，连续执行实现→必要验证→修复本任务引入的问题→交付，不为这些常规步骤逐次请求确认。新产品取舍、跨角色写入、公共契约变化、外部副作用及宿主权限仍按原边界处理；阻断只影响依赖它的任务。

同一 Part 已获准的独立任务可并行，前提是前置 PASS、文件无争用、构建/测试输出隔离且资源足够。不得为并行提前执行未来 Part；创建角色任务或子代理仍需实际授权。主线集成、共享状态更新串行，使用最终组合提交做必要集成复验。只读资料核验可批量进行；同一审阅者必要检查已通过且没有新变化/异常后，不无依据扩大测试。大型项目仍保留任务、Part、里程碑和最终审核，不切换为简化门禁。

不为节省 token 默认降低模型能力、删验收、限制必要推理、缩掉隐私边界或增加用户点击。无足够证据判断影响范围时扩大读取/验证。实际节省依项目和会话而变，不承诺固定费用比例或零错误率。
