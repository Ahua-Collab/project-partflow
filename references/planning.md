# 立项、角色和文件基线

## 与用户讨论

先了解使用者、一个输入到输出的真实使用流程、目标设备/离线需求、预算/时间/已有资料、必须使用的技术、数据来源与敏感性、用户如何判断完成。每轮只问会改变方案的问题，未知但可逆的选择先用明确默认值。将尚未确认的产品方向写为待决定，不假装已获认可。

先提出最小可用版本，再展开项目书。选型比较部署难度、设备资源、维护、费用与生态；不要把样例语言或原项目框架带入新项目。对关键不确定性安排小探针，依赖清单区分“拟用、已验证、已安装、失败”，记录精确版本、来源、许可、兼容性、资源代价和锁定方式。普通项目依赖按既有授权安装；系统级变更、付费、对外传数据等遵守实际权限。

## 项目书必须可派工

使用 [项目书模板](../assets/PROJECT_PLAN.md)，至少包括目标/不做、需求编号与验收、技术选型、模块接口、唯一所有权、数据/隐私、连续 Part 排期、里程碑、环境与交付要求。每个需求必须关联一个任务和可观察的验收；每个计划任务必须有唯一负责人、前置、允许路径、产出和验收。拒绝循环依赖、漏测的关键需求与无人负责的公共文件。

Part 编号由工作分解决定，不照搬固定分段数。把公共契约、根构建、数据库迁移、共享依赖安排在使用它们的业务任务之前。一个 Part 可先执行基础角色的前置，再执行业务角色主体；两个任务分别 prompt/review，整个 Part 门禁最后收口。可以同一 Part 并行互不依赖且不争用文件的任务；未来 Part 必须等待当前 Part PASS。

大型项目优先按可集成、可验收的成果划分 Part，把已满足依赖的独立模块安排在同一 Part；不要为每个机械动作新建一个 Part。每个里程碑安排跨模块验收与完整治理复核，避免长链只检查局部。保留全部门禁和证据结构；优化的是重复读取、转述和等待，不是验收强度。

按可独立交付模块划分角色，用职责名称生成简短 ID，不固定 A—F、部门数量或语言。小项目可只有总控和一个实现角色。用户希望开齐窗口时可以按其请求开齐，但尚未轮到的角色只初始化并等待，不能提前实现。总控与技术总监是同一个角色。专项补正窗口仅在有独立需求且获准委派时创建，父角色仍负责整合交付；子任务授权不超出父角色。

项目书、规则和 JSON 配置中的角色/排期必须一致。计划变更记录旧决定、原因、影响与需重验的要求；不能用删除必需任务或降低验收阈值使失败 Part 变成 PASS。产品方向的变化由用户决定，授权内的工程细化由总控落盘。

## 最小项目文件

新项目以以下相对路径为默认；接手旧项目先发现原路径，在配置中映射，不覆盖已有治理、不重编号已有 Part。

| 项目文件 | 来源/职责 |
|---|---|
| `PROJECT_PLAN.md` | [模板](../assets/PROJECT_PLAN.md)，产品、所有权、完整计划与验收依据 |
| `AGENTS.md` | [模板](../assets/AGENTS.md)，角色行为边界、必读材料和 Part 顺序纪律 |
| `docs/privacy-boundaries.md` | [模板](../assets/privacy-boundaries.md)，数据流与授权、生命周期、验证 |
| `.engineering/project.json` | [模板](../assets/project.json)，路径、主分支、角色、任务与里程碑映射，不存进度 |
| `.engineering/roles.md` | [模板](../assets/roles.md)，任务链接/ID、送达情况、当前设备定位、续任关系；缺 ID 用待确认，不伪造 |
| `progress/README.md` | [模板](../assets/progress-README.md)，记录和状态约定 |
| `progress/STATUS.md` | [模板](../assets/STATUS.md)，唯一进度入口 |
| `progress/Part-NN/` | 本 Part prompt、交付、review、补正和整个 Part 门禁 |

角色目录所有权以项目书为人可读权威；配置中的 `owners` 只是其机器校验映射，变更一起核对。路径用精确文件或 `/` 结尾目录前缀，不能重叠。公共构建、依赖锁、迁移、接口、发布配置及对应测试必须指定唯一所有者。治理目录归总控；角色交付报告默认由总控存档，实现角色只在明确授权的交付位置写文件。

初始化 Git、忽略缓存/秘密/本地定位文件，记录初始基线。构建骨架由基础设施所有者执行首个相应 Part，总控不越权代写实现。已有仓库保留用户未提交修改。主分支名可配置，不强制所有项目叫 main。

在已认可的项目范围内生成文件和任务提示词；若用户只要求讨论或设计，到所要求的产物为止。新任务的创建与发送遵守当前宿主和用户的明确授权；当前对话可直接作为总控，不强迫另开一个总控窗口。

## 隐私和存储

用 [隐私模板](../assets/privacy-boundaries.md) 描述来源授权 → 处理 → 存储 → 外部传输 → 导出/删除。明确功能处理与训练/遥测/上传的授权不同，原始与派生数据、日志、缓存、备份分别处理。无敏感数据或无持久化时写明核查结论，不创建空数据库模块。

有数据库才增加数据字典、迁移版本与唯一所有者、事务失败原子性、升级兼容、备份恢复、删除及失败报告验收。历史发布迁移不原地改写。法规问题按实际地区/数据核实，模板不是法律合规证明。示例测试优先使用合成数据，分发技能包不得夹带原项目对话、密钥或用户数据。
