# 中断、换机与 Git 交接

## 旧名称与格式

新项目使用 project-partflow、progress/Part-NN、schema_version: 2，以及 part、next_part、last_completed_part、completed_parts、end_part、due_part 字段。旧版的 Day 表示同一类逻辑工作单元；改名不允许改变编号、完成结论或依赖。

正在使用 daily/Day-NN 或 schema 1 的项目先按其原规则继续读取和人工核验，可保留旧版检查器；界面交流可称 Part，不能仅把 schema 改成 2、清空台账或将历史失败追认为 PASS。新检查器遇到旧格式会明确拒绝，不自动迁移。用户明确要求迁移某个实际项目时，再逐一映射字段、目录和所有引用，保留原归档及提交、形成可审查迁移记录，核对全历史证据后切换唯一 STATUS。新版技能的术语修改本身不授权改写已有项目治理。

## 找到权威治理来源

主工作区与角色工作树可能不同步。先用 Git 确认仓库身份、主分支、主工作树、当前 HEAD、状态和 worktree 列表；使用注册的治理来源读取最新项目书、规则、STATUS 和 progress。不要用旧工作树中的 Part 状态替代主线状态，也不要仅为读取提示词把治理提交强行重放到业务分支。必要时通过 `git show <主分支>:<相对路径>` 读取主线版本。涉及用户未提交治理变化时明确标识并对账，不把它当成已归档基线。

完成 SKILL.md 的必读清单后，输出当前 Part、角色、当前 prompt/review、未关闭项、原提交与主线提交、下一动作及可独立执行的同 Part 任务。对账冲突只暂停受影响的动作，能独立继续的只读核验继续。

## 窗口与任务

每个角色初始化使用 [role-start.md](../assets/role-start.md)，总控/角色续接使用 [handoff.md](../assets/handoff.md)。`.engineering/roles.md` 记录角色、任务 ID/链接或手工定位、父角色、活动/历史状态、首轮及当前 prompt、送达回执、代码工作树与治理来源。字段不承载进度，进度仍只在 STATUS。

先探测当前宿主实际可调用的创建、命名、读取、发送和项目归属能力；不要根据旧对话推断新设备也具备。用户已明确授权创建角色任务时可使用可用工具；创建返回 ID 后还需确认提示词送达、任务归属与初始状态。超时先查询既有 ID/同角色任务，避免重复创建。

没有任务工具时，提供“在当前项目创建名为……的任务，粘贴以下完整提示词，完成后将交付摘要带回总控”的说明。ID 无法取得可登记角色标题+用户手工确认，不能因无 ID 阻断手动流程，也不能宣称自动创建成功。用户在当前对话继续当总控时无需额外新建总控。技能不安装隐藏服务、不修改聊天数据库、不伪造工具，不把内部子代理或其他客户端的任务当成已经在当前侧边栏可见。

总控续任先落盘交接，确认新任务接收并恢复后转移活动标记。交接期间旧总控停止派工，新总控尚未接任时只恢复核验；不能两个窗口同时派工。历史窗口和 prompt 保留。技能没安装时，项目 AGENTS、项目书和交接提示词仍应足够恢复基本流程。

## Git 分叉与等价提交

- 审核前记录基线、完整源提交链和精确改动；保留用户文件。非冲突的未跟踪文件不自动意味着所有工作都必须停止，不自行清理它们。
- 合入是独立动作，执行前确定实际授权与文件所有者；实现者默认不合入，获明确限定的集成指令时可以只执行该动作。
- 主线已含原提交或经 cherry-pick/应用形成等价提交时，不重复合并。记录原 SHA → 主线 SHA；用精确 diff/内容核对，普通单提交可辅以稳定 patch-id。合并提交、冲突解决、二进制与空差异不能只用 patch-id 作唯一证明。
- 下一个 Part 从最新已验收主线建立或安全更新隔离工作树。旧角色分支无法快进时保留原历史，基于最新主线创建新分支/工作树；不要 reset/rebase/强切用户修改来满足流程。依照已有授权执行普通隔离操作，无需把每次分叉都变成新的用户决策。
- 同一 Part 补正在原交付分支追加聚焦提交，避免重写原提交。治理新增补正说明通过权威来源读即可。冲突涉及别的模块时交所有者处理，再独立审查冲突解决差异。
- 合入后在实际主线验证，再落最终 review。源码已合入而台账陈旧时只补验/补账，不再次合入。

## 跨设备与空间

治理文件、源码、Git 历史、锁文件、prompt/review 和验收所引用的脱敏证据随项目迁移。技能包单独安装。工作树目录、工具安装位置、缓存、任务 ID、当前权限重新发现；原机器定位只作历史线索。缺日志/提交对象时说明需恢复或重验，不能补造证据。移动项目后从新的根目录解析相对路径。

技能运行本身只需要文本读取能力；确定性检查器可选用 Node.js 与 Git，无第三方包。产品可只支持某一平台，流程的可移植不等于产品天然跨平台。

审计与实现使用独立构建输出目录，复用依赖下载缓存要防止不同配置互相裁剪同一安装树。已有成功安装且锁定一致时复用，别因中断重复下载。可清理的临时构建缓存先列出、确认目标与任务归属；保留待审提交、真实数据、未归档日志和原工作树。删除遵守用户授权，不把清理当作每轮必做动作。
